# week1 day4 习题答案
## 习题1

阅读 [`examples/simple/simple.cpp`](../../examples/simple/simple.cpp), 按以下顺序在 Day 1 图上标注调用:

   ```text
   ggml_backend_load_all
   -> llama_model_load_from_file
   -> llama_tokenize
   -> llama_init_from_model
   -> llama_batch_get_one(prompt)
   -> llama_decode
   -> llama_sampler_sample
   -> llama_batch_get_one(next token)
   -> llama_decode(one token)
   ```

答：
以下按普通 decoder-only Llama 模型路径标注。`simple.cpp` 中 prompt 首次处理和后续逐 token 生成共用同一个循环。

```text
初始化阶段
========

ggml_backend_load_all()
加载并注册 CPU/GPU 等计算后端
        |
        v
llama_model_load_from_file(...)
从 GGUF 加载模型权重、词表和模型结构
        |
        v

prompt 字符串
例如: "Hello my name is"
        |
        | llama_tokenize(...)
        | 第一次调用: 查询 token 数量
        | 第二次调用: 实际写入 prompt_tokens
        v
prompt token ids
实际 shape: [B,T] = [1,n_prompt]
Day 1 示例: [1,3]
        |
        | llama_init_from_model(...)
        | 使用 model 创建 context
        | context 保存计算状态和 KV cache
        v


Prompt prefill
==============

prompt token ids [1,T]
        |
        | llama_batch_get_one(prompt)
        | 将 T 个 token 包装成 llama_batch
        v
prompt batch
n_tokens = T
        |
        | llama_decode(ctx, batch)
        | 首次调用属于 prefill
        v
+------------------------------------------------------+
| llama_decode 内部对应 Day 1 模型数据流               |
|                                                      |
| token ids [1,T]                                      |
|       |                                              |
|       v                                              |
| embedding lookup，embedding table [V,D]              |
|       |                                              |
|       v                                              |
| hidden [1,T,D]                                       |
| Day 1 示例: [1,3,4]                                  |
|       |                                              |
|       v                                              |
| Transformer blocks                                   |
|       |                                              |
|       v                                              |
| output projection: D -> V                            |
|       |                                              |
|       v                                              |
| 概念上的 logits [1,T,V]                              |
| Day 1 示例: [1,3,8]                                  |
|       |                                              |
|       v                                              |
| last-position logits [V]                             |
| Day 1 示例: [8]                                      |
+------------------------------------------------------+
        |
        | llama_sampler_sample(smpl, ctx, -1)
        | -1 表示读取最后一个输出位置的 logits
        | 当前示例使用 greedy sampler
        v
next token id
第一个生成 token


逐 token decode
===============

next token id
        |
        | llama_batch_get_one(next token)
        | 包装成 n_tokens = 1 的 batch
        v
one-token batch [1,1]
        |
        | llama_decode(ctx, batch)
        | 使用 context 中已有的历史状态/KV cache
        v
embedding [1,1,D]
        |
        v
Transformer blocks
        |
        v
next-position logits [V]
        |
        | llama_sampler_sample(smpl, ctx, -1)
        v
再生成一个 token id
        |
        +----> llama_batch_get_one(next token)
               -> llama_decode(one token)
               -> 持续循环
```

这里有两个容易混淆的点：

1. `llama_batch_get_one()` 只包装 token，不执行 embedding 或模型计算。
2. `llama_decode(one token)` 不是计算刚刚采样出的 token。刚刚的 token 已经由前一次 logits 选出；这次 decode 是把它加入上下文，并计算再下一个 token 的 logits。

另外，`llama_batch_get_one()` 将 `batch.logits` 设为 `nullptr`。在当前 API 语义下，生成模型只输出最后一个 token 位置的 logits。因此 Day 1 的 `[1,3,8]` 是完整的概念图，而 `simple.cpp` 实际交给 sampler 的是最后位置 `[8]`。

对应源码位置：[simple.cpp](/home/king/llama.cpp/examples/simple/simple.cpp:82)。未修改 Day 1 Markdown 文件。


## 习题2
在 [`include/llama.h`](../../include/llama.h) 中定位 model/context/batch/sampler 的默认参数和释放函数。记录 n_ctx、n_batch 的含义; 暂不深入内部 graph。

答：
在 [llama.h](/home/king/llama.cpp/include/llama.h:255) 中可以整理为下面这张表：

| 对象 | 参数/默认参数 | 创建函数 | 释放函数 |
|---|---|---|---|
| model | `llama_model_params`；`llama_model_default_params()` | `llama_model_load_from_file()` | `llama_model_free()` |
| context | `llama_context_params`；`llama_context_default_params()` | `llama_init_from_model()` | `llama_free()` |
| batch | 没有 `default_params()` | `llama_batch_get_one()` 或 `llama_batch_init()` | `llama_batch_free()`，仅用于 `llama_batch_init()` 分配的 batch |
| sampler | `llama_sampler_chain_params`；`llama_sampler_chain_default_params()` | `llama_sampler_chain_init()` | `llama_sampler_free()` |

对应的最小生命周期：

```cpp
llama_model_params model_params = llama_model_default_params();
llama_model * model =
    llama_model_load_from_file(path, model_params);

llama_context_params ctx_params = llama_context_default_params();
llama_context * ctx =
    llama_init_from_model(model, ctx_params);

llama_sampler_chain_params sampler_params =
    llama_sampler_chain_default_params();
llama_sampler * sampler =
    llama_sampler_chain_init(sampler_params);

llama_batch batch =
    llama_batch_get_one(tokens, n_tokens);

// 使用 model/context/batch/sampler

llama_sampler_free(sampler);
llama_free(ctx);
llama_model_free(model);
```

`llama_batch_get_one()` 不分配 token 内存，只引用传入的 token 数组，所以不调用 `llama_batch_free()`。如果使用：

```cpp
llama_batch batch = llama_batch_init(...);
```

则必须：

```cpp
llama_batch_free(batch);
```

Sampler chain 会取得通过 `llama_sampler_chain_add()` 加入的子 sampler 的所有权。释放整个 chain 时会一起释放这些子 sampler，不能再单独释放它们。

**`n_ctx`**

```cpp
uint32_t n_ctx; // text context, 0 = from model
```

含义：context 能容纳的文本上下文长度，主要限制一条推理上下文中可保存和处理的 token 总量。

```text
prompt token 数 + 已生成 token 数 <= 可用 context 容量
```

设置为 `0` 表示从模型配置取得默认值。它影响 context/KV cache 所需容量。

**`n_batch`**

```cpp
uint32_t n_batch;
// logical maximum batch size that can be submitted to llama_decode
```

含义：单次提交给 `llama_decode()` 的逻辑最大 token 数量。

例如：

```cpp
ctx_params.n_ctx   = 4096;
ctx_params.n_batch = 512;
```

表示：

- 整个上下文最多约容纳 `4096` 个 token。
- 一次 `llama_decode()` 最多提交 `512` 个 token。
- 长 prompt 可以分批提交，每批不超过 `512`。
- 逐 token 生成时，每批通常只有 `1` 个 token。

所以二者不能混淆：

```text
n_ctx   = 整个会话的上下文容量
n_batch = 单次 llama_decode 调用的输入上限
```

头文件还说明，context 创建后实际采用的值可能与请求值不同，可以查询：

```cpp
llama_n_ctx(ctx);
llama_n_batch(ctx);
```

本次只定位了公共 API、参数和生命周期，没有进入内部 graph。

## FAQ
### 习题1 FAQ
为什么要调用llama_batch_get_one 将提示词 token 数组进行包装？ 直接分为 prefill 和 decode 两个过程不好吗？
答：
`llama_batch_get_one()` 的作用不是“把 token 数组复制一份”，而是把裸指针和 token 数量包装成 `llama_decode()` 能识别的 `llama_batch` 结构。

它实际返回的内容基本是：

```cpp
{
    .n_tokens = n_tokens,
    .token    = tokens,
    .embd     = nullptr,
    .pos      = nullptr,
    .n_seq_id = nullptr,
    .seq_id   = nullptr,
    .logits   = nullptr,
}
```

因此这一步主要提供了以下信息：

- 有多少个输入 token：`n_tokens`
- 输入来自 token id 数组：`token`
- 没有直接提供 embedding：`embd = nullptr`
- position 由 `llama_decode()` 自动跟踪：`pos = nullptr`
- 默认属于 sequence 0：`seq_id = nullptr`
- 默认只保留最后位置的 logits：`logits = nullptr`

所以：

```cpp
llama_batch batch =
    llama_batch_get_one(prompt_tokens.data(), prompt_tokens.size());

llama_decode(ctx, batch);
```

表示“用这批 prompt token 执行一次模型计算”。

这里的 `batch` 是必要的，因为 `llama_decode()` 不只支持“一个 token”，它还支持：

- prompt 的多个 token，即 prefill
- 单个新 token，即 decode
- 多个 sequence
- 显式 position
- 显式 sequence id
- 指定哪些 token 需要输出 logits
- 直接输入 embedding 而不是 token id

统一成 `llama_batch` 后，接口不需要分别设计：

```cpp
llama_prefill(...)
llama_decode_one(...)
llama_decode_batch(...)
llama_decode_multi_sequence(...)
```

而只需要一个：

```cpp
llama_decode(ctx, batch)
```

prefill 和 decode 的区别主要是批次大小和 context 状态：

```text
prefill:
batch.n_tokens = T
一次处理整个 prompt，并把 T 个 token 的 K/V 写入 KV cache

decode:
batch.n_tokens = 1
处理新 token，并在已有 KV cache 后追加一行
```

因此在应用层完全可以自己封装成两个函数：

```cpp
void prefill(llama_context * ctx, llama_token * tokens, int n) {
    llama_batch batch = llama_batch_get_one(tokens, n);
    llama_decode(ctx, batch);
}

void decode_one(llama_context * ctx, llama_token token) {
    llama_batch batch = llama_batch_get_one(&token, 1);
    llama_decode(ctx, batch);
}
```

但底层仍然需要 `llama_batch`。也就是说，“分成 prefill 和 decode 两个过程”是合理的语义划分；只是没有必要把它们做成两个完全不同的底层 API。

另外，`llama_batch_get_one` 是一个便捷的旧式 helper。需要控制 position、sequence 或 logits 时，应使用 `llama_batch_init()` 手动构造更完整的 batch。

### 习题2 FAQ
这个问题的意义是什么？
这个问题的意义不是背函数名，而是建立对 llama.cpp 公共 API 的整体认识。

它主要检查四件事：

1. **能否看懂对象生命周期**

   ```text
   model -> context -> batch/sampler -> 推理 -> 释放
   ```

   其中：

   - `model` 保存模型权重和词表；
   - `context` 保存一次会话的运行状态和 KV cache；
   - `batch` 是一次提交给模型的输入描述；
   - `sampler` 根据 logits 选择下一个 token。

   这样可以理解为什么通常要先创建 model，再创建 context，最后按依赖关系释放。

2. **能否区分“默认配置”和“实际运行对象”**

   ```cpp
   auto params = llama_context_default_params();
   params.n_ctx = ...;
   auto ctx = llama_init_from_model(model, params);
   ```

   `*_default_params()` 提供完整、兼容当前版本的初始配置，调用者只修改真正关心的字段，避免手动初始化遗漏字段。

3. **能否区分 `n_ctx` 和 `n_batch`**

   ```text
   n_ctx   = 整个会话最多能容纳多少 token
   n_batch = 一次 llama_decode 最多提交多少 token
   ```

   这是推理中非常重要的两个不同限制：

   - `n_ctx` 太小，可能导致上下文溢出；
   - `n_batch` 太小，长 prompt 需要拆成多次处理，影响吞吐，但不等于上下文容量变小。

4. **先掌握公共边界，再进入内部实现**

   题目要求暂不读 graph，是为了先回答：

   ```text
   应用代码需要创建什么？
   每个对象由谁拥有？
   每个调用的输入是什么？
   什么时候释放？
   ```

   之后再读 `llama_decode()` 内部 graph 时，才能知道 graph 是在为哪个 context、哪个 batch、哪个 KV cache 服务。

一句话概括：

> 这个问题是在训练“从 C API 头文件恢复运行时对象模型和资源生命周期”的能力，而不是单纯查找函数声明。
