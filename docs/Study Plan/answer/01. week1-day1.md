# week1 day1 习题答案
## 问题1 做小例子**: 使用 `V=8,D=4,T=3` 画 embedding lookup。任选 3 个 token id, 给每个 id 写一个 4 维向量; 用表格标出 lookup 前后 shape, 不需要模拟真实权重。
下面用 `V=8, D=4, T=3` 做一个小例子。先假设 `B=1`，也就是一次只处理一条序列。

`V=8` 表示词表里有 8 个 token id：`0..7`。  
`D=4` 表示每个 token id 对应一个 4 维嵌入向量。  
`T=3` 表示当前序列有 3 个 token。

假设输入 token ids 是：

```text
token ids: [2, 5, 1]
shape:     [T] = [3]
```

假设 embedding table 是：

| token id | 4 维 embedding 向量 |
|---:|---|
| 0 | `[0.10, 0.20, 0.30, 0.40]` |
| 1 | `[0.50, 0.10, -0.20, 0.00]` |
| 2 | `[-0.30, 0.80, 0.25, 0.60]` |
| 3 | `[0.90, -0.10, 0.40, 0.20]` |
| 4 | `[0.00, 0.70, -0.50, 0.30]` |
| 5 | `[0.35, -0.60, 0.15, 0.90]` |
| 6 | `[-0.75, 0.20, 0.55, -0.10]` |
| 7 | `[0.45, 0.45, -0.35, 0.25]` |

查表过程：

```text
2 -> [-0.30,  0.80,  0.25,  0.60]
5 -> [ 0.35, -0.60,  0.15,  0.90]
1 -> [ 0.50,  0.10, -0.20,  0.00]
```

所以 lookup 结果是：

```text
[
  [-0.30,  0.80,  0.25,  0.60],
  [ 0.35, -0.60,  0.15,  0.90],
  [ 0.50,  0.10, -0.20,  0.00]
]
```

shape 变化：

| 阶段 | 内容 | shape |
|---|---|---|
| lookup 前 | token ids | `[T] = [3]` |
| embedding table | 可学习查找表 | `[V, D] = [8, 4]` |
| lookup 后 | 每个 token 对应的嵌入向量 | `[T, D] = [3, 4]` |

如果带上 batch 维度 `B=1`，就是：

| 阶段 | shape |
|---|---|
| token ids | `[B, T] = [1, 3]` |
| embedding lookup 后 | `[B, T, D] = [1, 3, 4]` |

核心变化就是：

```text
[2, 5, 1]
```

变成：

```text
[
  embedding(2),
  embedding(5),
  embedding(1)
]
```

也就是每个 token id 从“一个整数”变成“一个长度为 `D=4` 的向量”。

## 问题2 接到输出: 假设 block 是恒等函数, 画 hidden [1,3,4] -> output projection [1,3,8] -> last-position logits [8]。标出生成时为什么只取最后一个位置。
假设前面的 embedding lookup 已经得到：

```text
hidden: [B, T, D] = [1, 3, 4]
```

并且 decoder block 是恒等函数，也就是：

```text
block(hidden) = hidden
```

所以进入输出层前仍然是：

```text
hidden [1, 3, 4]
```

可以把它画成 3 个位置，每个位置一个 4 维 hidden vector：

```text
position 0: h0 = [a0, a1, a2, a3]
position 1: h1 = [b0, b1, b2, b3]
position 2: h2 = [c0, c1, c2, c3]
```

输出投影把每个位置的 `D=4` 维向量映射到词表大小 `V=8`：

```text
output projection: D -> V
```

也就是：

```text
[1, 3, 4] -> [1, 3, 8]
```

画出来：

```text
hidden [1, 3, 4]

position 0: [a0, a1, a2, a3]
position 1: [b0, b1, b2, b3]
position 2: [c0, c1, c2, c3]

        output projection: 4 -> 8

logits [1, 3, 8]

position 0: [l00, l01, l02, l03, l04, l05, l06, l07]
position 1: [l10, l11, l12, l13, l14, l15, l16, l17]
position 2: [l20, l21, l22, l23, l24, l25, l26, l27]
```

shape 表：

| 阶段 | 含义 | shape |
|---|---|---|
| hidden | 每个位置一个 4 维隐藏向量 | `[1, 3, 4]` |
| output projection | 每个位置从 `D=4` 投影到 `V=8` | `[1, 3, 8]` |
| last-position logits | 只取最后一个位置的词表打分 | `[8]` |

生成时只取最后一个位置：

```text
last-position logits = logits[0, 2, :]
```

也就是：

```text
[l20, l21, l22, l23, l24, l25, l26, l27]
```

为什么只取最后一个位置？

因为自回归生成要预测的是：

```text
给定已有序列 [token0, token1, token2]，下一个 token 是什么？
```

在 causal mask 下：

```text
position 0 只能看 token0
position 1 能看 token0, token1
position 2 能看 token0, token1, token2
```

所以：

```text
position 0 的 logits 用来预测 token1
position 1 的 logits 用来预测 token2
position 2 的 logits 用来预测 token3，也就是下一个新 token
```

生成当前这一步，我们已经有了 3 个 token，要预测第 4 个 token，因此只需要最后位置 `position 2` 的 logits：

```text
[1, 3, 8] -> 取 logits[0, 2, :] -> [8]
```

一句话总结：

> 输出投影会给每个位置都算一组词表 logits，但生成时我们只关心“当前完整前缀之后的下一个 token”，而只有最后一个位置代表完整前缀，所以只取最后一个位置的 logits。


## FAQ
### 1. 不理解问题2中的 从D=4 映射到 V=8
可以把 `D=4 -> V=8` 理解成：

> 把“当前 token 位置的 4 个内部特征”，转换成“词表里 8 个候选 token 的分数”。

前面 hidden vector 是模型内部表示：

```text
h = [0.2, -0.5, 0.1, 0.7]   # D=4
```

它还不是“下一个 token 是谁”的答案。它只是模型内部的 4 维状态。

为了预测下一个 token，模型需要给词表里每个 token 一个分数。因为 `V=8`，词表有 8 个 token：

```text
token 0
token 1
token 2
token 3
token 4
token 5
token 6
token 7
```

所以输出必须有 8 个数：

```text
logits = [s0, s1, s2, s3, s4, s5, s6, s7]
```

其中：

```text
s0 = token 0 的分数
s1 = token 1 的分数
...
s7 = token 7 的分数
```

这个转换靠一个矩阵完成：

```text
W_out: [D, V] = [4, 8]
```

然后：

```text
h [4] × W_out [4, 8] = logits [8]
```

画成小图：

```text
hidden vector
[D=4]

[ h0 h1 h2 h3 ]

        ×

output weight
[D,V] = [4,8]

[
  [w00 w01 w02 w03 w04 w05 w06 w07],
  [w10 w11 w12 w13 w14 w15 w16 w17],
  [w20 w21 w22 w23 w24 w25 w26 w27],
  [w30 w31 w32 w33 w34 w35 w36 w37]
]

        =

logits
[V=8]

[ s0 s1 s2 s3 s4 s5 s6 s7 ]
```

每个输出分数都是 4 个 hidden 特征加权求和得来的：

```text
s0 = h0*w00 + h1*w10 + h2*w20 + h3*w30
s1 = h0*w01 + h1*w11 + h2*w21 + h3*w31
...
s7 = h0*w07 + h1*w17 + h2*w27 + h3*w37
```

所以 `D=4 -> V=8` 不是说“4 个东西变成 8 个东西”那么神秘，而是：

> 用一个 `[4,8]` 的输出权重矩阵，把 4 维内部表示转换成对 8 个词表 token 的打分。

之后 sampler 会根据这 8 个分数选择下一个 token。

### 2. D=4 表示 当前层的 hidden stat 向量值吗？
差一点点，应该这样说更准确：

`D=4` **不是 hidden state 的具体向量值**，而是 **hidden state 向量的长度 / 维度数**。

比如某一层、某个位置的 hidden state 可能是：

```text
h = [0.2, -0.5, 0.1, 0.7]
```

这里：

```text
D = 4
```

表示这个 hidden state 里面有 4 个数。

所以：

```text
D=4
```

描述的是 shape：

```text
hidden vector 的长度是 4
```

而不是描述值。真正的 hidden state 值是这 4 个浮点数：

```text
[0.2, -0.5, 0.1, 0.7]
```

在完整 shape 里：

```text
hidden [B, T, D] = [1, 3, 4]
```

含义是：

- `B=1`：一条序列
- `T=3`：三个 token 位置
- `D=4`：每个位置有一个长度为 4 的 hidden vector

可以画成：

```text
hidden [1, 3, 4]

position 0: [0.2, -0.5,  0.1,  0.7]
position 1: [0.4,  0.0, -0.3,  0.8]
position 2: [0.9, -0.1,  0.2, -0.6]
```

所以一句话：

> `D=4` 表示每个 token 位置的 hidden state 是一个 4 维向量；hidden state 的具体值是这个向量里的 4 个数。
