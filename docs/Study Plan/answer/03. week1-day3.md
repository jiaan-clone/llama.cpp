## 习题2 在习题1回答的基础上分析回答：在图上标出 RoPE 作用于 Q/K 的位置; 写一句话说明 GQA 中 `H` 个 Q heads 复用 `KvH` 个 K/V heads, 以及这如何减少 KV cache。
前面的手算省略了 RoPE，并且使用 `H=2、KvH=2`，属于普通 Multi-Head Attention。加入 RoPE 和 GQA 后，完整位置如下：

```text
hidden state X
    │
    ├─ XWQ → 拆成 H 个 Q heads
    │           │
    │        RoPE(Q, position) ─────────────┐
    │                                       │
    ├─ XWK → 拆成 KvH 个 K heads            │
    │           │                           │
    │        RoPE(K, position) ── transpose ├─→ Q'K'^T / √Dh
    │                                       │       → causal mask
    └─ XWV → 拆成 KvH 个 V heads            │       → softmax
                │                           │
                └───────────────────────────┴─→ 加权 V
                                                        │
                                              拼接 heads → WO
```

也就是：

$$
Q'=\operatorname{RoPE}(Q,\text{position})
$$

$$
K'=\operatorname{RoPE}(K,\text{position})
$$

$$
\operatorname{Attention}(Q,K,V)
=
\operatorname{softmax}
\left(
\frac{Q'K'^T}{\sqrt{Dh}}+M
\right)V
$$

RoPE 只作用于 `Q` 和 `K`，位置在 `QK^T` 之前；不直接作用于 `V`、softmax 或最终输出。它让 `QK^T` 的匹配分数包含 token 的相对位置信息。

前面的计算如果加入 RoPE，只需把：

```text
QK^T
```

替换为：

```text
RoPE(Q) · RoPE(K)^T
```

后面的 scale、mask、softmax 和加权 `V` 步骤不变。

**GQA 一句话说明：**GQA 将 `H` 个 Q heads 分组复用 `KvH` 个 K/V heads，使 KV cache 的 head 数从 `H` 降到 `KvH`，存储量约缩小为原来的 `KvH/H`。

例如，在前面的两头计算中设：

```text
H = 2
KvH = 1
```

则两个 Q head 保持独立，但共享一组 K/V：

```text
Q head 1 ─┐
           ├─→ 共享 K head 1 和 V head 1
Q head 2 ─┘
```

对于 `T=2、Dh=2`：

- 普通 MHA 的 KV cache：`2 × 2 × 2 × 2 = 16` 个数
- GQA 的 KV cache：`2 × 1 × 2 × 2 = 8` 个数

最后一个 `×2` 表示同时保存 K 和 V，因此这个例子中 GQA 将 KV cache 减少了一半。

## 习题3 做一张 prefill/decode 表: prompt 的多个 token 可以一起算, 新 token 通常一次追加一个; KV cache 保存历史 K/V, 避免每步重算历史。

| 对比项 | Prefill（提示词阶段） | Decode（逐 token 生成阶段） |
|---|---|---|
| 输入 | prompt 的多个 token | 最新生成的 token，通常一次 1 个 |
| 示例 | `[A, B, C]` 一起输入 | 先输入 `D`，下一轮输入 `E` |
| 计算方式 | 多个 token 可以并行计算 | 按生成顺序逐步计算 |
| Q/K/V | 计算 prompt 中所有 token 的 Q/K/V | 只计算新 token 的 Q/K/V |
| Attention | 每个 token 只能关注自己和之前的位置 | 新 token 关注自己及所有历史 token |
| KV cache | 将 prompt 各层的 K/V 写入缓存 | 读取历史 K/V，并追加新 token 的 K/V |
| 是否重算历史 K/V | 首次计算并保存 | 不重算，直接从 KV cache 读取 |
| logits | 通常使用 prompt 最后位置的 logits 生成首个 token | 使用当前新 token 的 logits 生成下一个 token |
| 并行程度 | 高，可沿 token 维度并行 | 低，后一个 token 依赖前一个 token |
| 常见瓶颈 | 计算量较大 | 频繁读取 KV cache，常受内存带宽限制 |

以 prompt `[A,B,C]` 生成 `D,E` 为例：

```text
Prefill:
输入 [A,B,C]
→ 计算 QA/B/C、KA/B/C、VA/B/C
→ KV cache = [KA/VA, KB/VB, KC/VC]
→ 使用 C 位置的 logits 生成 D

Decode 第 1 轮:
输入 D
→ 只计算 QD、KD、VD
→ QD 查询缓存中的 KA、KB、KC，并结合 KD
→ KV cache 追加 KD/VD
→ 生成 E

Decode 第 2 轮:
输入 E
→ 只计算 QE、KE、VE
→ QE 查询 A、B、C、D 的缓存，并结合 KE
→ KV cache 追加 KE/VE
→ 生成下一个 token
```

KV cache 只保存历史 **K/V**，不保存 Q，因为历史 Q 后续不会再使用；每一轮只需要新 token 的 Q 去查询全部历史 K/V。

### 习题作用
这个习题的作用是理解大模型推理的两个阶段，以及 KV cache 为什么重要：

- **Prefill**：一次处理整个 prompt，建立各层的 KV cache。
- **Decode**：每轮只处理一个新 token，复用历史 K/V，避免重复计算。
- **性能理解**：prefill 通常偏计算密集；decode 通常偏内存带宽密集。
- **源码衔接**：理解 `llama.cpp` 中第一次 `llama_decode()` 处理多个 prompt token，之后通常每次只处理一个新 token。

最终应能解释：**为什么 prompt 可以并行处理，而生成 token 必须顺序进行；以及没有 KV cache 时，为什么生成会越来越慢。**

## FAQ
### 问题1
针对第一道习题：
1. 为什么 每个维度 Dh=2？
2. scale 的计算公式为：Q K^T / sqrt(Dh) ，为什么你的步骤中 分子 Q K^T 变为 1？
3. 介绍 因果 Mask 矩阵中每个位置的含义。第一行的第二列是未来 token ，那么其他位置什么含义？

答：
1. 为什么 `Dh=2`？

`Dh` 表示每个 attention head 中 Q/K/V 向量的维度，不是 token 数量。

文档统一设定：

\[
D=4,\quad H=2
\]

因此：

\[
Dh=\frac{D}{H}=\frac{4}{2}=2
\]

也就是说，原始的 4 维 hidden state 被拆成两个 head，每个 head 处理一个 2 维向量。这里的 `Dh=2` 只是为了方便手算，实际模型通常更大。

---

2. 为什么 \(QK^T\) 的结果中出现了 1？

完整公式是：

\[
S=\frac{QK^T}{\sqrt{Dh}}
\]

其中 `1` 不是公式把 \(QK^T\) 变成了 1，而是我们选取的整数向量做点积后，恰好得到 1。

以 Head 1 为例：

\[
q_1=[1,0],\quad k_1=[1,0],\quad k_2=[1,1]
\]

那么：

\[
q_1\cdot k_1=1\times1+0\times0=1
\]

\[
q_1\cdot k_2=1\times1+0\times1=1
\]

对于第二个 query：

\[
q_2=[0,1]
\]

\[
q_2\cdot k_1=0,\qquad q_2\cdot k_2=1
\]

所以：

\[
QK^T=
\begin{bmatrix}
1&1\\
0&1
\end{bmatrix}
\]

再除以 \(\sqrt2\)：

\[
\frac{QK^T}{\sqrt2}=
\begin{bmatrix}
0.7071&0.7071\\
0&0.7071
\end{bmatrix}
\]

因此，分子并没有统一变成 1，而是每个位置都由对应的 Q、K 向量点积得到。

---

3. 因果 Mask 每个位置的含义

对于两个 token：

```text
token 1
token 2
```

Mask 为：

\[
M=
\begin{bmatrix}
0&-\infty\\
0&0
\end{bmatrix}
\]

矩阵的：

- 行表示“当前正在查询的 token”，即 Query。
- 列表示“被查询的 token”，即 Key。

| 位置 | 含义 | Mask 值 |
|---|---|---:|
| 第 1 行第 1 列 | token 1 查看自己 | `0`，允许 |
| 第 1 行第 2 列 | token 1 查看未来的 token 2 | \(-\infty\)，禁止 |
| 第 2 行第 1 列 | token 2 查看过去的 token 1 | `0`，允许 |
| 第 2 行第 2 列 | token 2 查看自己 | `0`，允许 |

加上 Mask 后，第一行第二列变成 \(-\infty\)。经过 softmax：

\[
e^{-\infty}=0
\]

所以 token 1 对 token 2 的 attention 权重为 `0`。这保证了生成 token 1 时不会提前看到未来的 token 2。

### 问题2
第一个习题的回答中，加权 V ，这个 V 是怎么来的？
加权计算中的 `V` 是我为了便于手算而**人为选取的整数向量**，不是从前面的 `Q`、`K` 计算出来的。

例如 Head 1：

\[
V_1=
\begin{bmatrix}
1&2\\
3&0
\end{bmatrix}
\]

含义是：

\[
v_{\text{token 1}}=[1,2]
\]

\[
v_{\text{token 2}}=[3,0]
\]

真实 Transformer 中，`Q/K/V` 都由输入 hidden state `X` 经过各自的线性投影得到：

\[
Q=XW_Q,\qquad K=XW_K,\qquad V=XW_V
\]

其中 \(W_Q,W_K,W_V\) 是模型训练得到的权重。`V` 不由 `QK^T` 产生；`QK^T` 只负责计算“应该从每个 V 中取多少信息”。

例如 Head 1 的 token 2 权重为：

\[
[0.3302,\ 0.6698]
\]

所以它读取两个 `V`：

\[
0.3302[1,2]+0.6698[3,0]
=[2.3396,0.6604]
\]

可以简单理解为：

- `Q`：我想找什么
- `K`：我包含什么特征，是否与 Q 匹配
- `QK^T`：匹配程度
- `V`：匹配后真正取回的内容

因此，之前例子中的 `V` 是为了演示最后的加权求和而预先给定的。

### 问题3
习题1 的练习目标是什么？
这个练习的目标不是记住具体数值，而是亲手走通 Attention 的完整数据流：

\[
Q,K,V
\rightarrow QK^T
\rightarrow \text{scale}
\rightarrow \text{causal mask}
\rightarrow \text{softmax}
\rightarrow \text{加权 }V
\]

完成后应理解：

- `QK^T` 计算 token 之间的匹配程度。
- `scale` 防止点积过大，使 softmax 更稳定。
- causal mask 阻止当前 token 看到未来 token。
- softmax 把分数转成总和为 `1` 的注意力权重。
- 加权 `V` 才是 Attention 最终提取的信息。
- 多个 head 分别关注信息，最后再拼接。

这些是后续理解 `llama.cpp` 中 Attention 计算图、KV Cache、prefill 和逐 token decode 的基础。

### 问题5
习题2中涉及到的 RoPE，如果没有经过 RoPE，那么token的位置就是乱序的？
不完全是“乱序”，更准确地说：**token 在张量中的排列仍然存在，但 Attention 不知道它们之间的明确位置和距离。**

没有 RoPE 时：

- causal mask 仍能保证 token 只能查看自己和过去，因此前后方向不会乱。
- `QKᵀ` 主要根据内容计算相关性。
- 对于所有允许查看的历史 token，模型缺少“它在前一个位置”还是“它在很远的位置”的直接信息。

例如当前 token 可以看到前面的 A、B，但如果没有位置编码，仅靠当前层的 Q/K，很难区分：

```text
A → B → 当前 token
B → A → 当前 token
```

RoPE 在 Q/K 中加入位置：

$$
Q'=\operatorname{RoPE}(Q,\text{position}),\qquad
K'=\operatorname{RoPE}(K,\text{position})
$$

这样 \(Q'K'^T\) 不仅表示内容是否相关，还包含两者的相对位置。

所以可以概括为：**causal mask 管“能不能看”，RoPE 管“看到的 token 在什么位置、相隔多远”。**

“对 Q/K 应用 RoPE”，它的主要优劣如下。

**优势**

- **注入相对位置信息**：Attention 能同时判断内容是否相关以及 token 相隔多远。
- **不需要位置嵌入表**：RoPE 使用固定旋转公式，基本不增加模型参数。
- **计算开销较小**：只对 Q/K 的成对维度进行旋转。
- **适合 KV cache**：历史 K 经过 RoPE 后可以缓存，生成新 token 时不必重复计算。
- **有一定长度泛化能力**：比固定长度的位置嵌入更容易扩展上下文。

**劣势**

- **超出训练长度后效果可能下降**：直接把上下文扩得很长，位置关系可能变得不可靠，通常需要 RoPE scaling。
- **存在旋转周期问题**：距离很远时，不同位置可能产生相近的旋转状态。
- **不能替代 causal mask**：RoPE只表示位置，不负责禁止查看未来 token。
- **增加少量计算和实现复杂度**：需要正确处理位置编号、旋转频率以及 KV cache 中 K 的位置。

简而言之：**RoPE 用很小的成本让 Attention 理解相对位置，但长上下文超过训练范围时需要额外的缩放策略。**
