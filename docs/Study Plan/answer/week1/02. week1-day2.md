## 问题1
画并标注下列结构, 每条箭头写 shape:
```text
   x [B,T,D]
     -> RMSNorm -> Attention [B,T,D] -> residual add -> x1 [B,T,D]
     -> RMSNorm -> FFN [B,T,D]       -> residual add -> x2 [B,T,D]
```

shape 表：

| 步骤 | 输入 shape | 输出 shape |
|---|---:|---:|
| `RMSNorm(x)` | `[B,T,D]` | `[B,T,D]` |
| `Attention(...)` | `[B,T,D]` | `[B,T,D]` |
| `residual add` | `[B,T,D] + [B,T,D]` | `x1 [B,T,D]` |
| `RMSNorm(x1)` | `[B,T,D]` | `[B,T,D]` |
| `FFN(...)` | `[B,T,D]` | `[B,T,D]` |
| `residual add` | `[B,T,D] + [B,T,D]` | `x2 [B,T,D]` |

关键点：两个 residual add 都要求左右两边 shape 完全一样，所以 Attention 和 FFN 最终都会回到 `[B,T,D]`。


### 用意
在学习计划里，画这个结构的用意不是为了“画图本身”，而是训练你建立 **一层 decoder block 的 shape 心智模型**。

Day 2 的目标很明确：先只建立数据流和 shape，不急着读复杂 C++。见 [001-llama-cpp-week1-daily-learning-route.md](</home/king/llama.cpp/docs/Study Plan/001-llama-cpp-week1-daily-learning-route.md:55>)。

这个图主要帮你确认几件事：

1. **一层 block 的输入输出 shape 不变**

   ```text
   x  [B,T,D]
   x1 [B,T,D]
   x2 [B,T,D]
   ```

   也就是说，decoder block 内部做了 Attention 和 FFN，但外部看起来还是：

   ```text
   [B,T,D] -> [B,T,D]
   ```

2. **residual add 为什么能相加**

   因为两边 shape 必须一样：

   ```text
   x [B,T,D] + Attention(...) [B,T,D]
   ```

   如果 Attention 输出不是 `[B,T,D]`，就不能直接 residual add。

3. **Attention 和 FFN 是“修改 hidden state”，不是改变 token 数量**

   `T` 没变，还是同一批 token 位置。  
   `D` 最后也没变，还是 hidden size。  
   变的是每个位置 hidden vector 里的数值内容。

4. **为后面读 Q/K/V、FFN、GGML graph 做铺垫**

   后面你看到 `RMSNorm`、`Q/K/V projection`、`ggml_add()`、`FFN up/down projection` 时，就能问：

   ```text
   输入 shape 是什么？
   输出 shape 是什么？
   是否还能接回 residual？
   ```

5. **区分 residual add 和 bias add**

   学习计划的验收也专门要求：能指出 residual add 不是 bias add。

一句话说：

> 画这个结构，是为了让你在进入 Attention 细节和 llama.cpp 源码之前，先掌握 decoder block 的外层骨架：两次 norm、两个子层、两次 residual，以及 `[B,T,D]` 这个 shape 不变量。

## 问题2
为每个子层补充输入/输出和不变量: RMSNorm 的权重 `[D]`; Q/K/V 投影; attention 合并回 `[B,T,D]`; FFN 中间维度 `I` 大于 `D`, 最后压回 `D`。

### 回答
下面是在原图基础上补全后的版本。先按 **不带 GQA 的普通 attention** 理解，`Dh = D / H`。
Dh = D / H 表示：每个 Attention Head（注意力头）分到的特征维度。
D：模型隐藏维度（hidden size）
H：注意力头数量
Dh：每个头的维度（head dimension）



```text
x [B,T,D]
  |
  | [B,T,D]
  v
RMSNorm_attn
  weight: [D]
  output: [B,T,D]
  |
  | [B,T,D]
  v
Q/K/V projection  (Q/K/V projection 包含了两步：线性投影 + 拆分多头。见FAQ解释)
  Q: [B,T,D] -> [B,H,T,Dh]
  K: [B,T,D] -> [B,H,T,Dh]
  V: [B,T,D] -> [B,H,T,Dh]
  |
  | Q/K/V: [B,H,T,Dh]
  v
Attention
  scores:  [B,H,T,T]
  context: [B,H,T,Dh]
  |
  | [B,H,T,Dh]
  v
merge heads
  [B,H,T,Dh] -> [B,T,H*Dh] -> [B,T,D]
  |
  | attention_out [B,T,D]
  v
residual add
  x [B,T,D] + attention_out [B,T,D]
  |
  | [B,T,D]
  v
x1 [B,T,D]


x1 [B,T,D]
  |
  | [B,T,D]
  v
RMSNorm_ffn
  weight: [D]
  output: [B,T,D]
  |
  | [B,T,D]
  v
FFN
  up/gate: [B,T,D] -> [B,T,I]
  activation/gate: [B,T,I] -> [B,T,I]
  down: [B,T,I] -> [B,T,D]
  |
  | ffn_out [B,T,D]
  v
residual add
  x1 [B,T,D] + ffn_out [B,T,D]
  |
  | [B,T,D]
  v
x2 [B,T,D]
```

对应公式：

```text
x1 = x  + Attention(RMSNorm_attn(x))
x2 = x1 + FFN(RMSNorm_ffn(x1))
```

子层输入/输出和不变量：

| 子层 | 输入 | 内部变化 | 输出 | 不变量 |
|---|---|---|---|---|
| `RMSNorm_attn` | `[B,T,D]` | 使用权重 `[D]` 对每个 token 的 hidden vector 做尺度归一化 | `[B,T,D]` | 不改变 `B/T/D` |
| `Q/K/V projection` | `[B,T,D]` | 投影成 Q/K/V，再 reshape 成 `[B,H,T,Dh]` | Q/K/V | `D = H * Dh` |
| `Attention` | Q/K/V `[B,H,T,Dh]` | 算 scores `[B,H,T,T]`，再加权 V 得到 context `[B,H,T,Dh]` | `[B,H,T,Dh]` | 不改变 token 数 `T` |
| `merge heads` | `[B,H,T,Dh]` | 合并 `H * Dh` | `[B,T,D]` | 最终必须回到 `D` |
| `residual add 1` | `x` 和 `attention_out` | `[B,T,D] + [B,T,D]` | `x1 [B,T,D]` | 两边 shape 必须相同 |
| `RMSNorm_ffn` | `[B,T,D]` | 使用权重 `[D]` | `[B,T,D]` | 不改变 shape |
| `FFN` | `[B,T,D]` | 先扩到 `[B,T,I]`，其中 `I > D`，最后压回 `[B,T,D]` | `[B,T,D]` | 中间可扩维，出口必须回到 `D` |
| `residual add 2` | `x1` 和 `ffn_out` | `[B,T,D] + [B,T,D]` | `x2 [B,T,D]` | 两边 shape 必须相同 |

核心记法：

```text
Attention: [B,T,D] -> 内部拆 Q/K/V 和 head -> [B,T,D]
FFN:       [B,T,D] -> [B,T,I] -> [B,T,D]
Block:     [B,T,D] -> [B,T,D]
```

所以一层 decoder block 的外部合同就是：

```text
输入 hidden state  [B,T,D]
输出 hidden state  [B,T,D]
```

中间可以拆 head、算 attention、扩 FFN 维度，但只要要接 residual，最后就必须回到 `[B,T,D]`。

### 用意
这个问题的用意是让你从“会背 Transformer 名词”走到“能追踪一层 decoder block 里的数据形状”。

它主要训练四件事：

1. **确认 decoder block 的外部合同**

   一层 block 看起来复杂，但整体必须是：

   ```text
   [B,T,D] -> [B,T,D]
   ```

   这样很多层才能连续堆叠。

2. **理解 residual add 的前提**

   残差相加不是随便加，必须满足：

   ```text
   [B,T,D] + [B,T,D]
   ```

   所以 Attention 和 FFN 最后都要回到 `[B,T,D]`。

3. **区分“内部 shape 变化”和“外部 shape 不变”**

   Attention 内部会变成：

   ```text
   Q/K/V: [B,H,T,Dh]
   ```

   FFN 内部会变成：

   ```text
   [B,T,D] -> [B,T,I] -> [B,T,D]
   ```

   但这些内部变化不能破坏 block 的输出合同。

4. **为读 llama.cpp / GGML graph 做准备**

   后面读源码时，你会看到 `RMSNorm`、`matmul`、`reshape`、`permute`、`ggml_add`。这个练习让你看到这些 op 时能立刻问：

   ```text
   输入 shape 是什么？
   输出 shape 是什么？
   这个 add 是 residual 还是 bias？
   为什么这里必须回到 D？
   ```

一句话总结：

> 这个问题的用意是训练你用 shape 追踪 Transformer，而不是只记概念；只要能看懂 `[B,T,D]` 如何在 Attention、FFN、residual 中保持一致，后面读 llama.cpp 的计算图就不会迷路。

## 问题3
回答“为什么 residual 两侧 shape 必须相同?”和“为什么 attention/FFN 前后仍保持 `[B,T,D]`?”
### 回答
**为什么 residual 两侧 shape 必须相同？**

因为 residual add 是逐元素相加：

```text
x1 = x + Attention(RMSNorm(x))
```

这里不是拼接，也不是矩阵乘法，而是：

```text
[B,T,D] + [B,T,D] -> [B,T,D]
```

同一个 batch、同一个 token 位置、同一个 hidden 维度上的数相加：

```text
x[b,t,d] + attention_out[b,t,d]
```

如果两侧 shape 不同，比如：

```text
[B,T,D] + [B,T,I]
```

那就不知道第 `d` 个 hidden 维度应该和谁相加，残差路径也无法保留原来的 hidden state 结构。

所以 residual 两侧必须 shape 相同。

**为什么 Attention / FFN 前后仍保持 `[B,T,D]`？**

因为 decoder block 的外部合同就是：

```text
输入 hidden state:  [B,T,D]
输出 hidden state:  [B,T,D]
```

这样下一层 decoder block 才能继续接上。

Attention 内部会拆 head：

```text
[B,T,D] -> Q/K/V -> [B,H,T,Dh]
```

但最后会合并回来：

```text
[B,H,T,Dh] -> [B,T,H*Dh] -> [B,T,D]
```

因为：

```text
H * Dh = D
```

FFN 内部会先扩维：

```text
[B,T,D] -> [B,T,I]
```

其中 `I > D`，但最后会压回：

```text
[B,T,I] -> [B,T,D]
```

所以：

```text
Attention: [B,T,D] -> [B,T,D]
FFN:       [B,T,D] -> [B,T,D]
```

一句话总结：

> residual add 要逐元素相加，所以两侧 shape 必须一样；Attention 和 FFN 内部可以变形、拆 head、扩维，但为了接 residual 和下一层 block，出口必须回到 `[B,T,D]`。

## FAQ
### 经历 Q/K/V projection 后，为什么  [B,T,D] 变为了 [B,H,T,Dh]
严格来说，`Q/K/V projection` 包含了两步：**线性投影 + 拆分多头**。

以 Q 为例：

### 1. 线性投影

输入：

```text
X: [B,T,D]
Wq: [D,D]
```

矩阵相乘：

```text
Q = X @ Wq
```

得到：

```text
Q: [B,T,D]
```

此时 shape 其实还没有变。

### 2. 把 `D` 拆成 `H × Dh`

因为：

```text
D = H × Dh
```

所以可以 reshape：

```text
[B,T,D]
→ [B,T,H,Dh]
```

再交换 `T` 和 `H` 两个轴：

```text
[B,T,H,Dh]
→ [B,H,T,Dh]
```

这样，每个注意力头都能独立计算：

```text
Q_head: [B,T,Dh]
K_head: [B,T,Dh]
V_head: [B,T,Dh]
```

例如 `D=4096`、`H=32`：

```text
[B,T,4096]
→ [B,T,32,128]
→ [B,32,T,128]
```

所以总元素数量没有变化：

```text
D = H × Dh = 32 × 128 = 4096
```

之所以写成 `[B,H,T,Dh]`，是为了把 `H` 个注意力头显式分开，方便并行计算每个头的：

```text
Attention(Q, K, V)
```

因此，更准确的流程是：

```text
[B,T,D]
  --线性投影--> [B,T,D]
  --reshape----> [B,T,H,Dh]
  --transpose--> [B,H,T,Dh]
```
