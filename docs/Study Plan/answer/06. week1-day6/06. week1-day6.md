## 习题2
**150-210 分钟, GDB 断点**: 运行:

   ```bash
   gdb --args ./build-study-debug/bin/llama-simple \
   ```

   在 GDB 中设置 `llama_model_load_from_file`、`llama_init_from_model`、`llama_context::decode`、`llama_sampler_sample` 断点。每次停住记录函数、prompt/decode 阶段、`batch.n_tokens` (或当前 batch 对应的 token 数)、`n_ctx/n_batch` 和返回值。

答：
1. 以Debug 构建方式，构建llama.cpp
```bash
cmake -S /home/king/llama.cpp \
  -B /home/king/llama.cpp/build-study-debug \
  -DCMAKE_BUILD_TYPE=Debug

cmake --build /home/king/llama.cpp/build-study-debug -j"$(nproc)"
```

2. 启动 GDB

`gdb --args ./build-study-debug/bin/llama-simple -m "/home/king/llama.cpp/deepseek-r1-1.5b-f16.gguf" -ngl 0 -n 4 "Hello"`

3. 在GDB 中依次输入

```bash
set pagination off # pagination：控制长输出是否分页 。off 关闭分页
set breakpoint pending on # breakpoint pending：控制“符号尚未加载时能否创建断点”。作用：libllama.so 是动态库，启动 GDB 时 llama_context::decode 可能尚未加载；GDB 会先建立“待解析断点”，程序加载动态库后自动绑定。

break llama_model_load_from_file # break 用于创建断点，简写为 b
break llama_init_from_model # break <location>， location 可以是： 函数名、文件:行号；内存地址；c++ 成员函数
break 'llama_context::decode(llama_batch const&)' # 单引号让 GDB 将整个 C++ 签名视为一个断点位置，避免 (、)、空格、& 被当成独立参数解析, 若该库已加载，也可尝试较短形式：break llama_context::decode 
break llama_sampler_sample

info breakpoints # info 用于查询 GDB 状态
run # run 启动被调试程序，简写为 r。
```
每次断住时可使用：
```bash
bt
info args
list
```

重点观察：
```bash
# llama_model_load_from_file
p path_model
p params.n_gpu_layers

# llama_init_from_model
p params.n_ctx
p params.n_batch

# llama_context::decode
p batch_inp.n_tokens
p batch_inp.token[0]

# llama_sampler_sample
p idx
```

观察完毕后继续执行：`continue` GDB 在首次命中断点时暂停；继续到下一个断点使用 continue

## 习题3
整理证据**: 画一条时间线, 明确第一次 decode 处理 prompt, 后续 decode 每次处理 1 个 token;
答：
```text
输入 prompt: "Hello"
tokenize 后: [BOS, H, e, l, l, o]
                 共 P 个 token

时间 ──────────────────────────────────────────────────────────────>

阶段 1：处理 prompt（Prefill）
┌──────────────────────────────────────────────────────────────────┐
│ batch = [BOS, H, e, l, l, o]                                    │
│ batch.n_tokens = P                                               │
│ llama_decode(ctx, batch)                                         │
│                                                                  │
│ 结果：                                                            │
│ - 模型计算 prompt 中各 token 的前向传播                           │
│ - KV cache 写入这 P 个 token 的 K/V                              │
│ - 最后一个位置产生 logits                                        │
└──────────────────────────────────────────────────────────────────┘
                                  │
                                  ▼
                         llama_sampler_sample()
                                  │
                                  ▼
                         得到第 1 个生成 token：T1

阶段 2：增量生成第 1 轮
┌──────────────────────────────────────────────────────────────────┐
│ batch = [T1]                                                     │
│ batch.n_tokens = 1                                               │
│ llama_decode(ctx, batch)                                         │
│                                                                  │
│ 复用：prompt 的 KV cache                                         │
│ 新增：T1 的 K/V 写入 KV cache                                    │
│ 输出：预测下一个 token 的 logits                                 │
└──────────────────────────────────────────────────────────────────┘
                                  │
                                  ▼
                         llama_sampler_sample()
                                  │
                                  ▼
                         得到第 2 个生成 token：T2

阶段 3：增量生成第 2 轮
┌──────────────────────────────────────────────────────────────────┐
│ batch = [T2]                                                     │
│ batch.n_tokens = 1                                               │
│ llama_decode(ctx, batch)                                         │
│                                                                  │
│ 复用：prompt + T1 的 KV cache                                    │
│ 新增：T2 的 K/V 写入 KV cache                                    │
└──────────────────────────────────────────────────────────────────┘
                                  │
                                  ▼
                         sample 得到 T3
                                  │
                                 ...
```

例如固定 `n_predict = 4` 时，GDB 中预期会看到：

```text
第 1 次 llama_decode: batch.n_tokens = prompt 的 token 数
第 2 次 llama_decode: batch.n_tokens = 1  # T1
第 3 次 llama_decode: batch.n_tokens = 1  # T2
第 4 次 llama_decode: batch.n_tokens = 1  # T3
```

最后采样出的 `T4` 通常不必再 `decode`，因为程序生成目标数量已经达到；只有还要继续预测下一个 token 时，才需要将 `T4` 再送入 `decode`。
